# 설계 Copilot

이 설치의 실행·회차·워크플로를 근거로 답하는 로컬 모델. **실행을 시작하지 않는다.**

## 준비 — 이 기계에서, 비용 0

```bash
ollama serve                 # 모델 서버
ollama pull exaone3.5:7.8b   # 4.8GB, 한국어. 16GB 메모리에서 여유
```

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `LOCAL_LLM_URL` | `http://127.0.0.1:11434/v1` | OpenAI 호환 채팅 엔드포인트 |
| `LOCAL_LLM_MODEL` | `exaone3.5:7.8b` | 모델 이름 |
| `LOCAL_LLM_TIMEOUT_S` | `120` | 한 답의 최대 대기 |

`GET /api/v1/copilot/status` 가 모델이 답하는지 말하고, 화면이 그걸 상태 줄에 보인다.

## 어떻게 답하는가 — 근거 주입

도구 호출이 아니다. 매 질문마다 서버가 **사실을 모아 시스템 메시지에 넣고**, 모델은 그 안에서만 답하도록 지시받는다.

| 넣는 것 | 한도 |
|---|---|
| 선택한 프로젝트와 회차(목표·실행 수) | |
| 최근 실행(상태·워크플로·회차·단계별 상태) | 8건 |
| 지정한 실행의 단계·지표·사건 | 지표는 수치·짧은 문자열만, 목록은 개수로, 사건은 마지막 12건 |
| 워크플로 정의(노드) | "실행할 수 있는 것이지 한 것이 아님"이라고 표시 |
| 전체 | 9,000자 |

답과 함께 **무엇을 참고했는지**가 돌아오고 화면에 「참고: …」로 붙는다. 틀린 답은 없는 사실로 추적한다.

## 왜 도구 호출이 아닌가

`exaone3.5:7.8b` 는 ollama 에서 도구 호출을 지원하지 않고, `qwen2.5:7b` 는 호출을 구조가 아닌 텍스트로 뱉는다.
7.8B 로컬 모델은 **보이는 데이터의 설명자**로는 쓸 만하고 **보이지 않는 데이터 위의 에이전트**로는 못 믿는다.
그래서 사실을 먼저 보여 주고, 실행 단추는 사람에게 남긴다.

## 첫 실제 질문에서 잡힌 것

실행이 0건인 프로젝트에 "최근 실행을 요약해 줘"라고 묻자, 모델이 **워크플로 정의를 실행 이력처럼** 서술했다 —
빈 제목 아래 아무것도 없으니 채워 넣은 것. 빈 항목은 이제 「없음」이라고 명시하고, 워크플로 절 제목에
"실행한 이력이 아님"을 붙였다. 고친 뒤 같은 질문에 "아직 실행이 이루어지지 않았습니다"라고 답했다.
회차 개설·실행 시작이 어느 화면인지도 프롬프트의 화면 지도에 적었다 — 처음엔 스튜디오로 안내했다.

## 시험

모델은 시험하지 않는다 — 가중치 파일이고 말하는 대로 말한다. 시험하는 것은 **모델에게 무엇을 건네는가**다:
이 설치의 사실인가, 길이가 묶였는가, 비밀 지표(`_` 접두)가 빠졌는가, 빈 항목이 「없음」인가, 답에 참고 목록이
붙는가. `platform/tests/test_copilot.py`, `web/src/pages/__tests__/copilot.test.tsx`.
