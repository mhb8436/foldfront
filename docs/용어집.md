# 용어집

화면과 문서에 나오는 용어를 한 자리에 모았다. **도메인 로직은 원본 RAPID v1.0.29 를 승계하며
수정하지 않는다.** 이 문서는 그 산출물을 읽기 위한 최소한의 사전이지 단백질 설계 교재가 아니다.

---

## 1. 파이프라인 7단계

정형 실행(`builtin-pipeline`)의 고정 순서다. 워크플로 스튜디오에서는 이 순서를 바꾸거나 분기를 넣는다.

```
msa → rfd3 → bioemu → design → soluprot → af2 → novelty
```

| 단계 | 읽는 이름 | 하는 일 | 받는 것 → 내는 것 |
|---|---|---|---|
| `msa` (`mmseqs`) | 다중서열정렬 | 대상 단백질과 닮은 서열을 공개 DB 에서 모아 정렬한다. 뒤 단계가 「이 자리는 진화적으로 보존됐다」를 판단하는 근거가 된다 | FASTA → A3M |
| `rfd3` | 백본 생성 | RFdiffusion3. 아미노산 서열은 비운 채 **3차원 뼈대 모양**만 여러 개 만든다 | PDB → PDB 여러 개 |
| `bioemu` | 구조 앙상블 | 한 구조가 실제로 취할 수 있는 **여러 자세**를 표본으로 뽑는다. 단백질은 고정된 조각이 아니라 움직인다 | PDB → PDB 여러 개 |
| `design` (`proteinmpnn`) | 서열 설계 | 뼈대를 주고 **그 모양이 되는 아미노산 서열**을 찾는다(역폴딩). 후보를 수십~수백 개 낸다 | PDB → FASTA |
| `soluprot` | 가용성 예측 | 그 서열이 대장균에서 **녹는지(응집되지 않는지)** 를 서열만 보고 점수로 낸다 | FASTA → 점수 |
| `af2` (`colabfold`) | 구조 예측 | AlphaFold2. 설계한 서열이 **의도한 모양으로 접히는지** 확인한다 | FASTA → PDB + 신뢰도 |
| `novelty` (`wt_diff`) | 신규성 평가 | 설계 결과가 원래 야생형 서열과 **얼마나 다른지** 센다. 너무 같으면 설계한 의미가 없다 | FASTA → 차이 수치 |

### 왜 이 순서인가

`design` 이 후보를 대량으로 내고, `af2` 가 가장 비싸다. 그 사이에 **싼 예측기(`soluprot`)로 먼저 거른다.**
원본의 정식 명칭 「Reproducible Pipeline for **Solubility-Oriented** Protein Redesign with
**Resource-Aware Surrogate Triage**」가 이 구조를 가리킨다 — 가용성 지향 재설계 · 자원 인지 대리 선별.

워크플로 스튜디오의 조건 분기식 `soluprot.pass_rate > 0.3` 이 그 장치다.
통과율이 낮으면 비싼 구조 예측으로 넘기지 않고 재설계로 되돌린다.

## 2. 그 밖의 모델

| 모델 | 하는 일 |
|---|---|
| `diffdock` | 도킹 — 단백질과 화합물이 **어떻게 맞물리는지** 자세를 예측한다 |
| `esm` | 서열을 수치 벡터로 바꾼다(임베딩). 유사도 비교·선별에 쓴다 |
| `rosetta relax` | 구조의 어색한 부분을 물리적으로 다듬는다 |

## 3. 화면에 뜨는 지표

| 지표 | 단계 | 뜻 | 높으면 |
|---|---|---|---|
| `depth` | msa | 모은 유사 서열 수 | 근거가 두텁다 |
| `coverage` | msa | 대상 서열 중 정렬된 비율 | 좋다 |
| `backbones` | rfd3 | 만든 뼈대 수 | 후보가 많다 |
| `mean_rmsd` | rfd3 | 기준 구조와의 평균 편차(Å) | **낮을수록** 원본에 가깝다 |
| `sequences` | design | 설계한 서열 후보 수 | 후보가 많다 |
| `pass_rate` · `passed` | soluprot | 가용성 기준 통과 비율 · 통과 개수 | 쓸 만한 후보가 많다 |
| `plddt` | af2 | 구조 예측 **신뢰도**(0~100) | 70 이상이면 믿을 만하다 |
| `rmsd` | af2 | 의도한 구조와의 편차(Å) | **낮을수록** 의도대로 접혔다 |
| `novel` | novelty | 야생형과 다른 자리 수 | 새롭다 |

★ **`plddt` 는 「구조가 좋다」가 아니라 「예측이 확실하다」는 뜻이다.** 구조 뷰어의 색이 이 값이며,
청색이 고신뢰 적색이 저신뢰다. 말단이 붉은 것은 대개 정상이다 — 끝부분은 원래 흔들린다.

## 4. 파일 형식

| 확장자 | 무엇 |
|---|---|
| `.fasta` | 아미노산 **서열**. `>이름` 줄 다음에 문자열이 온다 |
| `.pdb` | 3차원 **구조**. 원자마다 좌표 한 줄. B-factor 자리에 pLDDT 를 싣는 관행이 있다 |
| `.a3m` | 정렬된 서열 묶음(MSA 결과) |

## 5. 플랫폼 용어

| 용어 | 뜻 |
|---|---|
| **실행**(run) | 워크플로 한 번의 수행. 모든 이력·산출물이 `run_id` 에 매인다 |
| **실행 산출물**(artifact) | 각 단계가 낸 파일(PDB·FASTA·A3M·리포트). **과업 산출물과 다른 말이다** |
| **과업 산출물** | 계약에 따라 발주처에 제출하는 문서·매뉴얼·시험 결과서 |
| **워크플로 / DAG** | 실행 흐름. 노드와 방향 있는 간선으로 이루어지고 순환이 없다 |
| **노드 종류** | 모델(채움) · 변환 · 조건 분기(원형) · 병렬 분기(점선) · 합류 |
| **실행 층** | 동시에 돌려도 되는 노드 묶음. 위상 정렬이 정한다 |
| **Model Registry** | 모델을 고유 ID 로 등록하는 대장. URL 을 코드에서 고치지 않게 한다 |
| **동적 라우팅** | 모델 ID → 실행 위치 해석. RunPod → HTTP 워커 → 컨테이너 순 |
| **작업 큐 · 임대(lease)** | 워커가 작업을 일정 시간 점유한다. 워커가 죽으면 기한이 지나 자동 회수된다 |
| **fork** | 기존 실행의 특정 단계까지를 승계해 새 실행을 만든다. **원본은 손대지 않는다** |
| **모의 어댑터** | GPU 없이 흐름만 돌리는 대역. 지표는 난수다. **「동작한다」의 근거가 되지 못한다** |

## 6. 글로 쓸 때

- **아는 척하지 않는다.** 도메인은 「원본을 승계하며 수정하지 않는다」로 적고,
  우리 수행 범위는 플랫폼 공학으로 적는다.
- 「실행 산출물」과 「과업 산출물」을 **갈라 쓴다.** 섞으면 읽는 사람이 오독한다.
- 모의 어댑터가 낸 수치를 실측처럼 인용하지 않는다. 인용할 때는 모의임을 함께 적는다.
