# 동시 접속 실측

`tools/load_test.py` — 가상 사용자 N명이 콘솔 탭이 실제로 치는 조회(대시보드 요약 · 실행 목록 ·
알림 · 큐 통계 · 워크플로 · 프로젝트 · 실행 상세 · 사건 목록)를 간격을 두고 반복한다. 읽기만 하므로
운영 중인 설치에도 돌릴 수 있다.

```bash
uv run python tools/load_test.py --users 50 --seconds 30        # 요건 조건
uv run python tools/load_test.py --users 100 --seconds 20 --think 0.2
```

## 2026. 9. 17. 실측 — 개발 기계 1대 (API · MongoDB · 워커 동거)

|---|---|---|---|---|---|---|---|---|
| **50명 · 30초 · 간격 0.5초** | 2,923 | 0 | 96 | 0.006s | **0.058s** | 0.157s | 0.271s | **100%** |
| 100명 · 20초 · 간격 0.2초 | 5,291 | 0 | 262 | 0.052s | 0.663s | 1.897s | 5.131s | 99.7% |

요건(동시 50명 · 응답 3초)은 **50배 여유**로 충족한다. 원 JSON 은 `50users-30s.json` · `100users-20s.json`.

## 드러난 것

100명 조건에서 가장 느린 경로는 `/summary` (p95 1.58s). 대시보드 한 화면을 한 번의 호출로 그리려고
실행 200건·모델·워크플로·큐·감사 기록을 한꺼번에 읽는 구조라 부하가 여기로 몰린다. 요건 안에서는
문제가 아니지만, 이용자가 그 이상으로 늘면 **첫 후보는 `/summary` 의 실행 집계를 `$group` 한 번으로
바꾸는 것**이다(지금은 200건을 가져와 파이썬에서 센다).
